一、模块分层总览

这些文件可以理解为一条从“用户请求”到“工具执行”，再到“状态持久化与恢复”的主链路。 工具模块负责把能力暴露给 Agent；文件、路径、权限模块负责约束实际 IO；会话模块负责让上下文可恢复； Hook 与配置模块则负责把项目级策略注入运行过程。

工具入口层

将 Agent 的意图转换成具体操作，统一走权限、路径和结果包装。

  • SkillTool
  • FileReadTool / FileWriteTool / FileEditTool
  • GrepTool / GlobTool

文件与平台基础层

提供跨平台路径、文件读写、文件系统抽象、Shell Provider 与环境变量处理。

  • path / file / fileRead
  • fsOperations / filesystem
  • bashProvider / env / platform

会话生命周期层

负责会话文件定位、Transcript 读取、恢复、消息反序列化和工具结果外置存储。

  • sessionStorage / sessionStoragePortable
  • sessionStart / sessionRestore
  • conversationRecovery / toolResultStorage / sessionState

配置与 Hook 层

把项目配置、Markdown 配置、Agent 配置和 Hook 注册统一接入会话执行过程。

  • config / markdownConfigLoader / frontmatterParser
  • loadAgentsDir
  • hooks / hooksConfigSnapshot / sessionHooks

权限与校验层

解析权限规则，校验工具参数，让读写、Bash 前缀和文件模式具备一致的安全边界。

  • settings/permissionValidation
  • permissions/permissionRuleParser
  • settings/toolValidationConfig

通用支撑层

提供 JSON/JSONC 解析、错误识别、顺序执行控制等轻量基础能力。

  • json / errors
  • sequential

四、模块路径与功能分析表

下表将用户给出的模块名映射到仓库文件，并给出每个模块在系统里的定位。职责描述按代码语义归纳， 不是逐字翻译源码注释。

模块 文件路径 核心职责 主要协作对象 变更关注点
SkillTool src/tools/SkillTool/SkillTool.ts 提供技能调用入口，让 Agent 能按技能名称、参数和上下文执行扩展能力。 工具注册体系、配置、权限、会话上下文。 参数协议变化会影响所有技能调用；需要保持错误提示可定位。
sessionStorage src/utils/sessionStorage.ts 负责会话 transcript 的标准读写、路径管理和会话文件枚举。 sessionStoragePortable、sessionRestore、文件系统。 路径规则和文件格式必须兼容历史会话，否则 resume 会失效。
sessionRestore src/utils/sessionRestore.ts 从会话日志重建 Agent 状态、工具结果、工作区和恢复后的上下文。 conversationRecovery、toolResultStorage、计划与附件模块。 恢复逻辑需要兼容中断会话、旧格式日志和工作区切换。
toolResultStorage src/utils/toolResultStorage.ts 把较大的工具结果从主 transcript 中拆出，降低会话文件膨胀和读取成本。 会话存储、恢复逻辑、工具执行结果。 外置引用和实际文件必须保持一致，避免恢复时找不到结果内容。
sessionStoragePortable src/utils/sessionStoragePortable.ts 提供轻量、跨平台的会话文件读取和路径规整能力，适合快速加载摘要或恢复入口。 sessionStorage、conversationRecovery、项目路径。 读取头尾和路径 canonicalize 的行为会影响大 transcript 的性能与准确性。
conversationRecovery src/utils/conversationRecovery.ts 解析 JSONL transcript，恢复消息序列、技能状态、计划和中断上下文。 sessionRestore、sessionStart、toolResultStorage。 反序列化必须对损坏行、旧字段和中断状态保持容错。
sessionStart src/utils/sessionStart.ts 处理会话初始输入，并在会话启动或 setup 阶段触发受控 Hook。 hooks、hooksConfigSnapshot、插件 Hook。 启动 Hook 会影响首轮用户消息，需避免重复执行或越权执行。
FileWriteTool src/tools/FileWriteTool/FileWriteTool.ts 将完整文本写入指定文件，负责写入前的路径展开、权限检查和结果反馈。 file、fileRead、filesystem。 写入行为直接改变用户文件，必须正确处理新建、覆盖、编码和修改时间。
GrepTool src/tools/GrepTool/GrepTool.ts 基于文本模式搜索文件内容，面向代码定位和批量匹配场景。 ripGrep、fsOperations、权限检查。 搜索范围、隐藏文件、忽略规则和输出裁剪会影响结果可信度。
GlobTool src/tools/GlobTool/GlobTool.ts 按 glob 模式查找文件路径，适合先定位候选文件再交给读写工具处理。 glob、path、filesystem。 模式解析和相对路径输出要稳定，否则会影响后续工具链。
FileReadTool src/tools/FileReadTool/FileReadTool.ts 读取文件内容并按工具协议返回，通常包含范围读取、行号和大小限制。 fileRead、file、权限检查。 大文件、二进制文件和编码判断是主要边界。
FileEditTool src/tools/FileEditTool/FileEditTool.ts 对已有文件做局部替换或编辑，避免用整文件写入覆盖用户未预期内容。 file、fileRead、filesystem。 匹配唯一性、换行符、缩进和并发修改检测会影响编辑安全性。
path src/utils/path.ts 封装路径展开、相对路径转换、目录推导和配置键规范化。 文件工具、配置、权限模块。 Windows、WSL、Unix 路径差异会影响权限判断和展示路径。
file src/utils/file.ts 提供文件存在性、读写、编码、换行符、路径展示、行号处理等通用能力。 文件工具、fileRead、fsOperations。 这是高复用基础模块，任何异常处理变化都可能扩散到多个工具。
frontmatterParser src/utils/frontmatterParser.ts 解析 Markdown 文件开头的结构化元数据，为配置和 Agent 定义提供元信息。 markdownConfigLoader、loadAgentsDir。 解析失败应保留正文可用性，避免单个 frontmatter 错误阻断整份配置。
loadAgentsDir src/tools/AgentTool/loadAgentsDir.ts 从 Agent 目录加载定义文件，将 Markdown 配置转换为可运行的 Agent 描述。 frontmatterParser、markdownConfigLoader、工具注册。 目录遍历、命名冲突和无效 Agent 文件需要清晰反馈。
markdownConfigLoader src/utils/markdownConfigLoader.ts 读取 Markdown 配置，把正文和 frontmatter 合并为统一配置对象。 frontmatterParser、json。 配置字段校验要和调用方期望保持一致。
fsOperations src/utils/fsOperations.ts 集中封装文件系统操作，让工具层不直接绑定具体 fs 实现。 文件工具、搜索工具、文件基础模块。 抽象层改动会影响测试替身、真实文件系统和错误分类。
bashProvider src/utils/shell/bashProvider.ts 选择和描述可用 Bash/Shell 执行环境，为命令执行提供平台适配。 platform、env、Shell 执行器。 Windows 和 WSL 环境下的可用 Shell 判断要特别谨慎。
env src/utils/env.ts 集中读取和解释环境变量，减少业务代码散落读取 process env。 配置、平台、工具执行。 环境变量默认值和布尔值解析会影响运行模式。
filesystem src/utils/permissions/filesystem.ts 判断路径是否在允许工作区内，并为读写工具生成权限检查结果。 permissionRuleParser、文件工具、配置。 这是文件安全边界，任何放宽都需要明确业务理由。
config src/utils/config.ts 管理全局配置、项目配置、信任状态、默认值和配置文件路径。 工具、Hook、权限、会话、项目目录。 配置 schema 和默认值调整要兼容旧用户配置。
hooks src/utils/hooks.ts 提供 Hook 加载、执行、过滤和结果处理，是外部脚本介入运行流程的主入口。 hooksConfigSnapshot、sessionHooks、配置。 Hook 执行涉及安全、超时、错误传播和输出注入，需要保持黑盒测试覆盖。
settings/permissionValidation src/utils/settings/permissionValidation.ts 校验配置中的权限规则是否符合工具语义和规则格式。 permissionRuleParser、toolValidationConfig。 错误信息要能指导用户修复配置，而不是只给出技术异常。
permissions/permissionRuleParser src/utils/permissions/permissionRuleParser.ts 在字符串形式权限规则和结构化规则对象之间转换，并兼容历史工具命名。 权限校验、配置、文件系统权限判断。 转义和反转义必须可逆，否则保存后的规则可能无法恢复。
settings/toolValidationConfig src/utils/settings/toolValidationConfig.ts 描述不同工具的权限规则校验方式，例如文件模式工具、Bash 前缀工具和自定义校验。 permissionValidation、工具定义。 新增工具时需要同步补充校验配置，避免权限配置接受无效规则。
fileRead src/utils/fileRead.ts 读取文件时补充编码、换行符等元数据，为显示和编辑保持原始格式提供依据。 file、文件工具。 编码识别和换行符检测会影响后续写回是否产生无关 diff。
json src/utils/json.ts 提供 JSON、JSONC、JSONL 的安全解析和局部更新工具。 配置、会话恢复、Markdown 配置。 安全解析应返回可诊断错误，避免调用方直接崩溃。
errors src/utils/errors.ts 集中识别常见错误类型，帮助调用方按错误原因给出不同处理。 文件、配置、工具执行、恢复逻辑。 错误分类过粗会导致用户提示不准确，过细则会增加维护成本。
hooksConfigSnapshot src/utils/hooks/hooksConfigSnapshot.ts 捕获和读取会话级 Hook 配置快照，让恢复过程使用一致的 Hook 策略。 hooks、sessionStart、配置。 快照必须明确区分托管 Hook、用户 Hook 和完全禁用 Hook 的状态。
sessionState src/utils/sessionState.ts 保存当前会话运行态，并向监听者广播元数据、权限模式等状态变化。 UI、会话恢复、权限模式、Agent 执行。 状态通知需要避免重复触发或遗漏关键变化。
sequential src/utils/sequential.ts 提供任务串行化执行能力，避免同类异步操作并发修改共享状态。 Hook、会话、文件或配置更新链路。 串行化边界过宽会影响性能，过窄会留下竞态。
platform src/utils/platform.ts 识别当前平台、Linux 发行版、WSL 版本和版本控制系统信息。 bashProvider、路径、文件系统、配置。 平台识别错误会连锁影响 Shell 选择和路径处理。
sessionHooks src/utils/hooks/sessionHooks.ts 维护会话内注册的函数 Hook 和会话 Hook，为运行期扩展点提供存取 API。 hooks、会话状态、工具执行。 Hook 增删需要以 sessionId 隔离，避免跨会话串扰。

五、模块边界与维护建议

工具层改动 优先检查参数 schema、权限检查、路径展开、错误提示和测试说明是否同步。
文件基础层改动 关注 Windows/Unix/WSL 差异，以及编码、换行符、隐藏文件和大文件边界。
会话层改动 必须验证旧 transcript、恢复中断、外置工具结果和工作区恢复路径。
配置与 Hook 改动 需要明确配置来源优先级，并验证 Hook 禁用、托管 Hook、用户 Hook 的组合场景。
权限层改动 任何解析或校验变化都应覆盖 allow、deny、ask、历史命名和转义字符。
通用工具改动 保持 API 小而稳定，错误返回要让上层能继续给出可读诊断。

建议的阅读顺序

  • 先看 config、hooks、filesystem，理解运行策略从哪里来、如何被约束。
  • 再看 FileReadTool、FileWriteTool、FileEditTool、GrepTool、GlobTool，理解工具如何消费基础能力。
  • 最后看 sessionStorage、conversationRecovery、sessionRestore，理解执行后的状态如何被持久化并恢复。
